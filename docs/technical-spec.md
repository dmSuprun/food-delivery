# Технічне завдання (базова версія)

**Назва:** Сервіс замовлення та доставки їжі з ресторанів.

Онлайн-сервіс, який дозволяє користувачам обирати ресторани поблизу, формувати та оплачувати замовлення
онлайн і відстежувати доставку в реальному часі; ресторани керують меню та замовленнями, кур'єри отримують
завдання на доставку.

## Цільова аудиторія
Замовники (клієнти), ресторани, кур'єри, адміністратори.

## Функціональні вимоги
1. Реєстрація та автентифікація з розмежуванням ролей (клієнт, ресторан, кур'єр, адміністратор) — `auth-service`.
2. Перегляд каталогу ресторанів і меню з пошуком та фільтрацією (категорія, ціна, рейтинг) — `restaurant-service`.
3. Оформлення замовлення та онлайн-оплата через платіжний шлюз — `order-service`, `payment-service`.
4. Відображення статусу замовлення та геолокації кур'єра — `delivery-service`.
5. Адмін-панель ресторану для керування меню та замовленнями.
6. Оцінки та відгуки про ресторани й кур'єрів.
7. Єдине API для мобільних і веб-клієнтів.
8. Push/SMS/email-сповіщення про зміну статусу — `notification-service`.

## Нефункціональні вимоги
- Доступність ≥ 99.9%.
- Горизонтальне масштабування мікросервісів під пікові навантаження.
- Автовідновлення після збоїв.
- Час відгуку API ≤ 200–300 мс.
- Шифрування даних, зберігання секретів в Azure Key Vault.

## DevOps-стек
Azure, Java 17 + Maven, JUnit 5, Jenkins (CI/CD), Docker + ACR, AKS, Postman/Newman,
Azure Monitor + Managed Grafana, Terraform (IaC), Azure Key Vault.

## Етап 1 (поточний)
Git-репозиторій зі структурою мікросервісів, базове ТЗ, CI/CD-конвеєр Jenkins (Maven build + JUnit +
архівування JAR) на кожен коміт.
